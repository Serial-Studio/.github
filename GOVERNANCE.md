# Governance

Serial Studio is a single-maintainer project. **Alex Spataru** (@alex-spataru) is the
author, maintainer, and copyright holder, and makes the final decision on the roadmap,
architecture, releases, and what is merged.

## How decisions get made

Technical direction is discussed in the open, in issues and
[Discussions](https://github.com/Serial-Studio/Serial-Studio/discussions). Anyone can argue
for a change, and good arguments regularly change the plan. When there is no consensus, the
maintainer decides.

Larger changes should be discussed in an issue before the code is written. That is not a
formality: it is the cheapest point to find out that a feature belongs somewhere else in the
architecture, or that it conflicts with the licensing split.

## Licensing and the commercial model

The project is dual-licensed. The GPLv3 build is free software and stays that way. The Pro
modules are commercially licensed, and revenue from Pro licenses is what funds full-time
work on the project, including the GPL parts.

Because a single entity must be able to license the code under both sets of terms, all
contributions are accepted under the Contributor License Agreement in
[CONTRIBUTING.md](CONTRIBUTING.md). Contributions to both the GPL code and the Pro modules
are welcome.

Which side of the line a given feature falls on is a maintainer decision. Every source file
carries an SPDX header stating its license; check it before you start work.

## Maintainership

There is currently no formal committer process. Contributors who show sustained, high-quality
involvement may be given triage or commit rights at the maintainer's discretion. Trademark,
release signing, distribution channels, and the commercial license remain with the
maintainer.

## Code of Conduct

Participation in every space run by this organization is governed by the
[Code of Conduct](CODE_OF_CONDUCT.md). Enforcement is handled by the maintainer at
alex@serial-studio.com.
